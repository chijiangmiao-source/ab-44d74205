# 地面标定推导表

128 格（A1–H16）推导表：每格可填有符号 64 位整数常量，或由加、减、乘、整除、
单元格引用及条件式 `if(条件,真值,假值)` 组成的公式；支持提交单格候选修改并查看裁决。

> 公式额外提供向零取整的整数除法 `/`，用于覆盖验收要求的“除零”失败场景。

## 运行（Compose，可配置宿主机端口）

```bash
HOST_PORT=8080 docker compose up --build   # 宿主机端口由 HOST_PORT 指定，默认 8080
```

- 页面：`http://localhost:8080/`
- 健康：`GET /health` → `{"status":"ok","generation":N}`（Compose 已配置健康检查）

无 Docker 时也可直接运行同一应用：`PORT=8080 python3 server.py`（仅依赖 Python 3.11 标准库）。

## 一次性验收

```bash
./verify                 # 或 HOST_PORT=9090 ./verify
```

`verify` 自动依次执行并以退出码报告结果（0 通过 / 1 失败）：

1. **构建检查**：`python3 -m compileall` 编译全部源码；
2. **代码测试**：`unittest` 引擎单元测试 + HTTP 集成测试；
3. **启动服务**：优先 `docker compose up -d --build`（`HOST_PORT` 可配置），
   无 Docker 时回退为本地进程启动同一应用；
4. **API/HTTP 冒烟与场景验收**（`acceptance/run.py`，真实 HTTP 请求）：
   - 页面 `/` 与健康 `/health` 冒烟；
   - **条件切换**：新分支实际引用、依赖新增/移除、不沿用旧分支缓存；
   - **部分下游发布**：受影响项共同进入新代次，其余项值与缓存代次不变；
   - **失败回滚**：环路 / 未知引用 / 除零 / 64 位溢出，校验从候选格到首个
     失败点的稳定链路，且活动表、依赖边、缓存值、缓存代次均保持修改前状态。

完成后自动清理（`docker compose down` 或结束本地进程）并退出。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 页面 |
| GET | `/health` | 健康响应 |
| GET | `/api/state` | 活动表（值、代次、活动依赖）与依赖边 |
| POST | `/api/candidate` | 提交单格候选：`{"cell":"A1","input":"if(C1, A1, A2)"}`；发布返回 200，拒绝返回 409 |
| POST | `/api/reset` | 清空全表（便于验收场景隔离） |

## 裁决语义

- **活动依赖**：仅按实际进入的条件分支确定；`if` 未取分支不产生依赖，其中的
  未知引用/除零/溢出也不会触发。
- **暂存重算**：候选先结合*修改前*的反向活动依赖求受影响闭包，在独立暂存区
  重算并替换依赖边；非受影响项直接命中已发布缓存。
- **原子发布**：全部暂存成功才将受影响项以同一新代次原子发布；裁决报告展示
  缓存命中、重算明细与依赖变更（新增/移除）。
- **失败回滚**：环路、未知引用、除零、64 位整数溢出任一发生即整体回滚，
  报告给出从候选格到首个失败点的稳定链路（确定性求值顺序保证可复现）。

## 结构

```
app/formula.py     公式解析（AST）
app/evaluator.py   暂存求值：活动分支依赖、int64 检查、失败链路
app/engine.py      推导表：受影响闭包、暂存→原子发布/回滚、代次管理
app/server.py      HTTP 服务（页面/健康/状态/候选）
app/static/index.html  页面
tests/             单元与集成测试
acceptance/run.py  HTTP 冒烟与场景验收
verify             一次性验收入口
Dockerfile / docker-compose.yml
```
